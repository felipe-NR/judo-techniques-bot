# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Reddit bot (praw) that streams comments from the subreddits in `SUBREDDITS`, detects Japanese judo technique names, replies with the English names and a video link, and records every detection in PostgreSQL. Python 3.13, managed with `uv`.

## Commands

Run everything from the repository root: `config.py` opens `.bumpversion.toml` by relative path, and the tests open `tests/techniques_test_data.pickle` by relative path.

```bash
uv sync --dev                     # install
uv run -m judo_techniques_bot     # run the bot (applies pending migrations first)
docker compose up                 # bot + postgres + adminer (adminer on :9001)
uv run -m judo_techniques_bot.load_data   # load data/techniques_fixtures.csv into the DB

uv run -m unittest                                        # all tests
uv run -m unittest tests.test_bot.UnitTestBot.test_build_technique_pattern_single_word   # one test
uv run coverage run -m unittest && uv run coverage report

uv run ruff check                 # lint (CI)
uv run ruff format --check        # format check (CI)
uv run ty check                   # type check (CI)

uv run alembic -c judo_techniques_bot/alembic.ini revision --autogenerate -m "message"
uv run alembic -c judo_techniques_bot/alembic.ini upgrade head
```

`alembic.ini` lives inside the package, not at the root, so alembic needs `-c` when run from the root. Running it from inside `judo_techniques_bot/` instead fails with `ModuleNotFoundError: No module named 'judo_techniques_bot'`: `prepend_sys_path = .` resolves against the working directory, and `migrations/env.py` imports the package.

CI (`.github/workflows/cy.yml`) runs ruff check, ruff format check, `ty check`, and unittest on pushes and PRs to `main`.

## Architecture

- `config.py` reads every setting from environment variables with `os.environ[...]` at import time, so importing almost any module without the full `.env.example` set raises `KeyError`. `db.py` creates the SQLAlchemy engine at import time. `tests/test_bot.py` works around both by importing inside a `mock.patch.dict("os.environ", ...)` plus `mock.patch("sqlalchemy.create_engine")` block; new test modules need the same wrapper.
- `__main__.py` sets up Sentry and logging (stdout plus `logs/all.log`), then calls `main.main()`, which runs `alembic upgrade head` programmatically and starts the bot. An uncaught exception is logged and sent to Sentry, and the process exits; there is no in-process restart loop (a `while True` loop existed until commit `e9e8a2f`). In production, `restart: always` in `docker-compose-portainer.yaml` restarts the container.
- `Technique.get_cached_techniques()` loads all techniques once at startup into a dict keyed by every entry in each technique's `japanese_names` array. Adding or editing techniques in the DB requires a bot restart to take effect.
- `Bot` (`bot.py`) precompiles one regex per Japanese name variant (`_build_technique_pattern`: words joined by an optional space or hyphen, wrapped in `\b` word boundaries, with an optional trailing `s` for English plurals) and matches it against the lowercased comment body. Each comment goes through a pipeline over `MentionedTechnique` records: detect, mark duplicates within the comment as `will_be_posted=False`, mark techniques the bot already translated anywhere in the same submission (by scanning the bot's own comments) as not posted, save every detection as a `DetectedJudoTechniqueMentionEvent` (with `translated` = `will_be_posted`), then reply with the remaining ones. On a `RedditAPIException`, `_reply_to_comment` retries up to `MAX_RETRIES` times with `time_between_retry` (10 min) sleeps, except when `_is_unrepliable` finds one of `Bot.EXCEPTION_ERRORS` (the target comment is gone), which returns without retrying.
- `tests/techniques_test_data.pickle` is a snapshot of the `get_cached_techniques()` dict used to build `Bot` in tests without a database. `utils.pickle_dictionary` can regenerate it.
- Migrations live in `judo_techniques_bot/migrations` (filenames dated by `file_template` in `alembic.ini`). `migrations/env.py` overrides the URL with `config.DATABASE_URI` and suppresses empty autogenerated revisions. New models must be imported in `env.py` for autogenerate to see them.
- `load_data.py` bulk-inserts the CSV without checking for existing rows, and `japanese_display_name` is unique, so it only works against an empty `techniques` table. In the CSV, `japanese_names` and `english_names` are comma-separated lists inside one quoted field.

## Versioning and deployment

The `bump-version` workflow bumps the patch version in `.bumpversion.toml` and commits it on every push to `main`; do not edit the version by hand. `config.VERSION` (`jtb-<version>`) is reported to Sentry as the release. Production runs the Docker image on a Portainer VPS (`docker-compose-portainer.yaml`); the Terraform/AWS setup and `.github/archived/` workflows are no longer used.
